
===================== КОРРЕКЦИЯ ТРЕКЕРА (этот раунд) — старый список выше был устаревшим =====================

При попытке "добавить всю физику сразу" перепроверил весь server.cpp grep'ом по пунктам списка "ОТЛОЖЕНО" выше
и оказалось, что он был устаревшим — в какой-то момент раньше были добавлены вещи, которые он 100%
называл нереализованными, а запись об этом в трекер не попала. Фактически уже реализованы и есть в коде:

- KELP_GROWTH_V1 — водоросли растут (тот же счётчик-паттерн, что у сахарного тростника/кактуса/бамбука).
- Вьюны (weeping_vines вниз, twisting_vines вверх, cave_vines вниз с шансом на ягоды) — растут.
- CORAL_DEATH_V1 — кораллы/фаны/блоки без воды тухнут в dead_-вариант.
- CAULDRON_V1 — котёл наполняется водой по уровням, тушится рядом с лавой.
- SAPLING_GROWTH_V1 — саженцы растут в деревья (упрощённо: dark oak растёт с одиночного саженца, а не с 2x2 кластера, как в ванилле).
- STEM_GROWTH_V1 — pumpkin_stem/melon_stem растут по age и выпускают плод на свободную соседнюю клетку.
- FROSTED_ICE melt — frosted_ice тает обратно в воду со 0временем (без связи с light API — у него свой таймер).
- TURTLE_EGG / SNIFFER_EGG — яйца трескаются/вылупляются со временем.

Всё это было в коде ДО этого раунда (вероятнее всего добавлено в одном из предыдущих раундов про RANDOM_TICK_V1,
просто не было честно вынесено в трекер). Ничего из этого не переделывал — просто чиню запись.

===================== ANTILAG_TNT_V1 + ANTILAG_SET_V1 (этот раунд) =====================

Причина: репорт про провал сквозь пол после /set (в консоли видно MiniEdit set: 2583784 блоков,
затем MiniEdit set: 59820280 блоков, следом Сервер лагает! Текущий TPS: 4.34 из 20). Плюс отдельный
запрос — общий лимит TNT в мире.

1) ANTILAG_SET_V1 — общий потолок объёма для /set, /replace и /copy (там же неявно ограничивает
   /paste, т.к. paste ограничен тем, что скопировано copy'ем): 8 000 000 блоков за одну операцию.
   Проверка добавлена в единой точке validateSelection() в miniedit.hpp, так что покрывает все три
   команды разом. При превышении — команда просто отклоняется с сообщением, блоки не трогаются.
   Это и есть основной фикс провала сквозь пол: раньше /set ничем не ограничивался и мог поставить
   59 млн блоков за раз, забивая тик-луп и вызывая рассинхрон коллизии на клиенте.

2) ANTILAG_TNT_V1 — общий потолок TNT в мире: 8 000 000 суммарно (активные подожжённые TNT-сущности
   + просто стоящие непойджённые TNT-блоки). Новый счётчик tntBlockCount_ (atomic) считает стоячий
   TNT, активные считаются уже существующим primedTnt_.size(). Счётчик обновляется в чётырёх точках:
   - установка TNT-блока игроком (пакет Use Item On, generic-ветка постановки блока) — увеличение,
     и здесь же новая проверка отказа, если лимит уже достигнут;
   - слом TNT-блока игроком (Player Action) — уменьшение;
   - primeTntBlock() (поджиг кремнём/огнивом, цепные реакции подрыва) — уменьшение при переходе
     блок -> сущность;
   - publishMiniEditChanges() — единая точка для /set, /replace, /paste, /undo, /redo и цепного
     разрушения TNT при взрыве (startBulkTntCollapse/tickBulkTntCollapse) — считает переходы блока
     до/после на 2095.
   Важное честное ограничение: счётчик стартует с 0 при запуске сервера — это НЕ полное сканирование
   уже существующего мира на предмет старого TNT, который мог быть поставлен раньше (сканирование
   всего мира по чанкам слишком дорогое). То есть лимит считает TNT, появившийся/удалённый начиная
   с этого изменения, а не абсолютное количество TNT в мире с начала времён.
   Не трогал редстоун-активацию TNT (диспенсеры и т.п.) — это чисто счётчик и отказ в постановке/
   поджиге сверх лимита, а не новая логика поджига.

Не проверено на живом сервере (нет доступа к запущенному инстансу в этой среде) — только по коду
и балансу скобок (лексер-скрипт).

=== VEHICLE_PHYSICS_V1 (лодки + вагонетки) ===
Лодки (entity type 10):
- Установка предмета лодки (oak..bamboo_raft, id 774/776/778/780/782/784/786/788/790) спавнит сущность,
  а не блок. Порода дерева передаётся метадатой (индекс 11, VarInt) — если клиент покажет дуб, дело в этом поле.
- Управление клиент-авторитетное, как в ваниле: клиент присылает Move Vehicle (0x1E),
  сервер валидирует прыжок (не больше 32 блоков за такт) и рассылает Teleport Entity (0x70) остальным.
- Paddle Boat (0x1F) зеркалится метадатой (12/13, Boolean) — гребки видно другим игрокам.
- Без пассажира лодка плавает на воде (всплытие +0.02, кап 0.1) и падает под гравитацией 0.04 на суше.
Вагонетки (entity type 69, предмет 766):
- Ставится ТОЛЬКО на рельсы (клик по рельсе или по блоку, рядом с которым рельса).
- Физика серверная: движение по геометрии рельс — проверяются 4 соседние клетки на y, y+1, y-1,
  разворот назад запрещён, выбирается направление с максимальным dot к текущему.
  Форма рельсы (RailShape) НЕ читается из блокстейта: таблица item_blocks.gen.hpp имеет дырки,
  которые не совпадают с ванильным количеством стейтов, поэтому биты формы там недостоверны.
- Разгон пассажиром: +0.012/такт, кап 0.4; трение 0.985 без пассажира, 0.96 при отпущенном W;
  подъём -0.012, спуск +0.008; сход с рельс — гравитация + столкновение с землёй.
- Ускоряющие/нажимные/активирующие рельсы работают как обычные (редстоун вне области, по договорённости).
Общее:
- Посадка: правый клик по транспорту (Use Entity 0x16, тип 0/2) -> Set Passengers (0x5F).
- Выход: Player Input (0x26) флаг 0x02 (shift).
- Атака (Use Entity тип 1) уничтожает транспорт, дропает предмет (не в креативе), Remove Entities (0x42).
- Позиция пассажира синхронизируется каждый такт (setPosition), чтобы окружение тикало корректно.
- ANTILAG: припаркованный транспорт не рассылает пакеты; лимит 4096 транспортов.
НЕ СДЕЛАНО (осознанно): сундук-лодки/вагонетки, TNT/воронка/печь/спавнер/командная вагонетка,
настоящая логика стрелок и развилок, поведение powered/detector/activator рельс,
восстановление транспорта для игроков, зашедших позже (список vehicles_ не рассылается при входе).

=== VEHICLE_FIX_V2 + RAIL_SHAPE_V1 (по отчёту с теста) ===
1. Лодка на воде: при клике по воде ищем вершину водяного столба и ставим лодку туда
   (раньше на горе воды целевой блок был воздухом и лодка не ставилась).
2. Сундук-лодки: отдельный тип сущности chest_boat = 17, item 775/777/.../791 -> variant 0..8.
   Инвентаря внутри НЕТ — только катание и визуал.
3. Высадка: игрок ставится на y+1.0 от транспорта + принудительный 0x40 (Synchronize Player Position),
   чтобы клиент не уронил игрока на блок ниже.
4. Форма рельс (главное): выведена раскладка стейтов из порядка свойств ваниллы:
   rail = SHAPE(10) x WATERLOGGED(2), шаг формы 2; powered/detector/activator = SHAPE(6) x POWERED(2) x WATERLOGGED(2), шаг 4.
   При установке рельса выбирается форма по соседям (прямая / поворот / подъём),
   соседние рельсы пересчитываются и рассылаются пакетом 0x09 (потому же исчезали энерго-рельсы:
   клиент предсказывал свою форму, сервер не подтверждал свою).
5. Физика вагонетки теперь идёт по двум выходам формы рельсы, а не по угадыванию по соседям:
   повороты и подъёмы едут корректно, езда в обе стороны (S при малой скорости разворачивает).
6. Лодка не ломается с одного удара: 3 удара рукой (поле hits), в креативе сразу; на каждый удар шлётся 0x24.
   Топор НЕ выделен — id топоров не проверены, не угадывал.
НЕ СДЕЛАНО: инвентарь сундук-лодок; редстоун-поведение powered/detector/activator (форма теперь верная, ускорения нет);
пересчёт форм при ЛОМКЕ рельсы; рассылка уже существующего транспорта при входе игрока.

=== MULTIWORLD_V1 (Ад + Энд, первый подход) ===
Сделано:
- Три отдельных мира: world_ (обычный), nether_, end_. Поле player->dimension (0/1/2).
- worldFor(dim) / worldOf(player) / ensureDimensionReady(dim) / travelToDimension(...).
- Плоская генерация пресетами: setFlatPreset(1) = бедрок + три слоя незеррака,
  setFlatPreset(2) = бедрок + три слоя end_stone. Стоим на Y=4, миры бесконечные.
- Join Play теперь анонсирует все три level id (без этого клиент режет Respawn в Ад/Энд).
- Смена измерения: Respawn 0x47 (data kept 0x03) + Game Event 13 + clearSeenChunks()
  + стрим чанков нового мира + два синхрона позиции 0x40.
- Маршрутизация блоков: в handlePlay и sendChunksAround локальная ссылка world_ затеняет
  член класса — все 279 обращений игрока автоматически уходят в его измерение.
- Команды (op): /nether, /end, /overworld. Пересчёт координат 1:8 обычный<->Ад,
  Энд — платформа у (0.5, 5, 0.5), возврат в обычный мир ищет поверхность сверху.

НЕ СДЕЛАНО (честно):
- НЕТ порталов как блоков: обсидиановая рамка + огниво ничего не зажигает,
  переход пока только командой. Аналогично нет портала Энда и end_portal_frame.
- Физика вне handlePlay (вода/лава, падающие блоки, TNT, дропы, транспорт,
  сундуки, random tick) работает ТОЛЬКО в обычном мире.
- Игроки видят друг друга между измерениями (нет фильтра по dimension в броадкастах).
- Ад/Энд не сохраняются на диск и не грузятся — при рестарте генерятся заново.
- player->dimension не пишется в playerdata: после релога игрок всегда в обычном мире.
- Нет механик Ада/Энда: лавовые моря, адские крепости, острова Энда, дракон,
  свет Ада, вода не испаряется, кровати не взрываются. Миры плоские, как договорились.
- НЕ СОБИРАЛОСЬ локально (MSVC только у тебя). Ожидаемые предупреждения: C4458
  (локальный world_ скрывает член класса) — это задумано, не баг.

[MEM_V4] world/chunk.hpp, world/chunk.cpp, core/server.cpp
  Ответ на «500 МБ при старте, а плоский 24 МБ»: секция хранила плоский
  std::array<u16,4096> = 8 КБ ВСЕГДА. Плоский мир трогает 1 секцию из 24,
  обычный рельеф — ~13 -> разница ровно в 13 раз, что и видно (24 против 500).
  Стало: paletted + bit-packed хранилище (как в ванильном PalettedContainer):
   - однородная секция (весь камень / весь воздух) = 0 байт данных, bits=0;
   - <=16 состояний (почти всё подземье и рельеф) = 4 бита на блок = 2 КБ;
   - дальше палитра растёт 5/6/7/8 бит, после 256 состояний — direct 15 бит (как было).
  Внутренний формат СОВПАДАЕТ с сетевым paletted container 1.21.1, поэтому writeTo()
  льёт его как есть: пакет Chunk Data упал с 8 КБ/секцию до ~2 КБ — трафик и время
  отдачи чанков тоже в разы меньше, побочкой.
  Плюс keepRadius в pruneAllWorlds: было viewDistance+3, стало +1 (два лишних кольца
  чанков висели в ОЗУ без толку: при r=10 это 729 колонн против 529).
  Ожидаемо: стартовые ~500 МБ -> порядка 60-90 МБ.
  API секции не менялось (setBlock/getBlock/writeTo), anvil.cpp и ворлдген не трогал.
